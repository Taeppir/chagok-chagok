# MVP 검증 기록

검증 환경: Pleos ARM64 Emulator API 34, 앱 0.5.0. 실제 도로 주행이 아닌 Virtual Console 입력을 Vehicle SDK와 앱의 기록 서비스가 수집한 결과입니다.

## 세 가지 주행 사례

| 항목 | 처음 만난 바다 | 할머니 집 불빛 | 조개구이 가는 길 |
|---|---:|---:|---:|
| 수집 시간 | 42초 | 50초 | 48초 |
| 유효 속도 표본 | 35 | 34 | 34 |
| 속도 중앙값 | 22 km/h | 45 km/h | 78 km/h |
| 로컬 비트 템포 | 84 BPM | 94 BPM | 104 BPM |
| 와이퍼 상태 변화 | 0 | 1 | 0 |
| 창문 상태 변화 | 2 | 0 | 10 |
| 문 상태 변화 | 2 | 6 | 2 |
| 깜빡이 상태 변화 | 2 | 0 | 10 |
| 설정 온도 변화 | 1 | 3 | 2 |
| 내기 순환 변화 | 0 | 3 | 2 |
| 선택 장르 | 어쿠스틱 | 로파이 | 힙합 |
| 오디오 분석 가사 구간 | 27 | 22 | 21 |

횟수는 SDK가 전달한 상태 변화 수입니다. 와이퍼의 왕복 횟수나 방향지시등 전구의 점멸 횟수가 아닙니다. 비 오는 시나리오에서 콘솔의 Low/High 전환을 여러 번 조작했지만 앱의 와이퍼 상태 콜백은 1회 변화로 집계됐습니다. 관측값을 그대로 기록했습니다.

인물과 이야기는 창작한 시나리오입니다. 가족·친구의 실제 대화를 공개한 자료가 아닙니다. APK의 `assets/demo-songs`에 MP3와 가사·편곡 정보를 포함했습니다. `demos/verified`의 JSON에는 콘솔 시계열, SDK 집계, 생성 요청, 파일 해시가 있습니다.

## 재현성과 비용

- 같은 편곡 입력을 두 번 렌더링한 PCM이 바이트 단위로 같습니다.
- 세 사례의 PCM이 서로 다릅니다. 차량 온도·내기 순환 변화도 출력 PCM을 바꿉니다.
- 셰이커·벨·클랩·림샷·신스·퍼커션·베이스·드럼의 단독 미리듣기 8개가 서로 다르며 약 3초 뒤 끝납니다.
- 세 AI 생성 요청을 다시 전송했을 때 기존 ID와 저장된 곡이 반환됐습니다. 재생은 생성 API를 호출하지 않습니다.
- AI 보컬곡은 로컬 비트의 파형을 입력받지 않습니다. 템포·장르·신호별 밀도를 텍스트로 전달하는 방식이며, 최종곡이 정확히 같은 BPM과 리듬을 유지한다고 보장하지 않습니다.
- 가사 타이밍은 완성 음원을 한 번 분석한 결과를 저장합니다. 모델 추정이므로 전문 강제 정렬 수준의 정확도를 보장하지 않습니다.

## 실행 검증

- Android 직접 instrumentation: 5개 통과. 8개 악기 분리, 공조 매핑, 속도 부족 시 기본 템포, 결정적 렌더링, 실제 세 사례의 차이.
- Python 단위 검증: 13개 통과. 중복 과금 방지, 재시작 후 캐시, 불확실한 요청의 자동 재시도 금지, 입력 범위, 대화 요약 캐시.
- Debug/Release 빌드와 Android Lint 통과. Gradle 연결 테스트 태스크는 오프라인 UTP 의존성 문제로 사용하지 않고 설치 후 `am instrument`로 실행했습니다.
- 네 탭과 사용법·믹스·보관함·제목·공유 창을 실제 화면에서 조작했습니다. 기본 글씨와 1.3배 글씨, 모션 축소 상태도 확인했습니다.
- MP3와 WAV를 MediaStore의 `Download/Chagok`에 저장한 뒤 파일명과 크기를 조회했습니다.
- Android 공유 선택창 호출은 확인했지만 이 에뮬레이터에는 음원 파일을 받을 앱이 없어 실제 앱 간 전송 완료는 검증하지 못했습니다. Bluetooth와 온라인 공개 성공으로 소개하지 않습니다.
- Pleos 앱 목록과 하단 바로가기에 비율을 유지한 실버 로고가 표시됩니다. 예전 Buds3 진단 앱은 본 앱과 별개입니다.

## 검증 범위의 한계

짧은 한국어 테스트 음성의 녹음·전사·요약 경로를 검증했습니다. 30분은 수집 상한으로 구현했지만 30분 연속 내구성, 실차 소음, 여러 사람의 겹치는 발화는 아직 검증하지 않았습니다. 원음 삽입·음성 복제·웃음 감지·자동 영상 편집은 구현하지 않았습니다. 온라인 커뮤니티는 사용자 소유 서버와 인증·공개 동의·삭제 정책을 연결한 뒤 검증해야 합니다.

## 풍부한 악기 조합 시연

편집·풀 버전 영상에는 추가 콘솔 주행도 담았습니다. 58초 동안 속도 표본 37개, 중앙값 70 km/h, 가감속 변화, 와이퍼·창문·깜빡이·설정 온도·내기 순환 각 18회, 문 16회가 기록됐습니다. 총 106회의 장치 상태 변화로 104 BPM 힙합 비트와 8개 악기 미리듣기를 시연했습니다. 많은 이벤트를 짧게 압축한 기능 시연이며 일반 운전자의 실제 행동 빈도나 실차 시험을 뜻하지 않습니다.

- 편집본: 약 3분 2초. 두 기록 세션과 세 창작 사례를 목적에 맞춰 편집했으며, 생성 대기 축약 구간을 표시했습니다.
- 풀 버전: 약 11분 42초. 두 실기동 챕터를 정상 속도로 연결했습니다. 실제 AI 생성 대기와 파일 저장, 수신 앱이 없는 공유 선택창까지 포함합니다.
- 음성 입력은 한국어 합성 테스트 문장을 사용했습니다. 창작 시나리오 세 곡과 실제 사람의 비공개 대화를 혼동하지 않도록 구분했습니다.
- 영상에는 앱에서 출력한 비트·악기·보컬 음원을 사용했습니다. 편집본의 설명 장면 배경음은 검증된 로컬 비트를 사용했습니다.
