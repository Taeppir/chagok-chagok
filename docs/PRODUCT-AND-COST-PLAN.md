# 차곡차곡: 구현 범위와 저비용 상용화 설계

검토일: 2026-11-15. 아래에서 **현재 구현**, **추가 개발**, **실차 검증 필요**를 구분한다. 이 문서는 상용화 설계안이며, 현재 에뮬레이터 앱을 운영 서비스로 보장하는 문서가 아니다.

## 제품의 한 문장

**달린 길과 나눈 말을, 한 곡으로.**

가족을 주요 대상으로 삼되 친구·연인·혼자 하는 이동도 담는다. 차량에서 일어난 변화를 음악의 재료로 쓰고, 사용자가 선택한 이야기를 가사로 만든다.

## 화면과 이용 흐름

1. 주행 화면에서 **주행 시작**. 차량 데이터만 또는 대화 포함을 선택하고, 주행 중 화면 조작은 제한하면서 시작한 기록을 계속한다.
2. 주차 후 **주행 마치기 → 주행 리포트 → 장르 선택 → 비트 듣기**. 실제 수집 수치를 먼저 확인하고 로컬 비트를 들어본다.
3. **여행 이야기**에서 짧게 말하거나 직접 입력한다. 생성 전 실제로 보낼 내용·참여자 이름·장르를 확인한다.
4. **음악 만들기**를 눌렀을 때만 가사와 AI 보컬곡을 생성한다.
5. 플레이어에서 CD와 파형, 가사를 보며 듣는다. 제목 수정은 기기의 메타데이터만 바꾼다.
6. 공개는 별도 선택이다. 닉네임·제목·음원·가사와 음성 포함 여부를 확인하고 최종 동의 후 업로드하는 구조로 확장한다.

현재 앱은 Android 파일 저장·공유를 제공한다. 공개 서버 연결 및 실제 업로드·다른 사용자 곡 탐색 검증은 아직 완료되지 않았다. 업로드되지 않은 것을 공개 완료로 표시하지 않는다.

## 무엇이 현재 가능한가

| 가사와 보컬곡 | Lyria 3.5에 이야기·이름·장르·목표 BPM·악기 밀도 정보를 보낸다. 생성된 MP3를 내려받아 저장한다. |
| 비트와 완성곡의 관계 | 로컬 비트 WAV를 Lyria에 입력하지 않는다. 같은 편곡 정보를 텍스트로 전달한다. 비트의 파형·박자·BPM을 정확히 유지하는 방식은 아니다. |
| 제목 | 초안 제목을 표시하며 사용자가 수정할 수 있다. 제목 수정 때문에 음악을 다시 생성하지 않는다. |
| 가사 표시 | 플레이어 내부에서 읽는다. 오디오 분석 시간 정보가 있는 곡은 재생 위치에 맞춰 두 줄로 표시한다. 모델 추정이므로 정밀한 싱크를 보장하지 않으며, 시간 정보가 없으면 수동 스크롤로 제공한다. |
| 데이터 수집 | 현재 차량 신호 세션은 최대 30분 후 자동 저장한다. 원본 속도 표본은 요약 후 폐기한다. 프로세스 강제 종료 시 복구되는 장시간 기록은 별도 개발해야 한다. |

Pleos가 필요한 이유는 스마트폰만으로 알기 어려운 차량 장치의 실제 변화를 수집하기 때문이다. 지도상의 이동 속도만 쓰는 음악 앱과 달리, 차 안의 동작이 음악 재료로 나타난다. 단, 와이퍼의 **상태 전환 횟수**는 실제 블레이드 왕복 횟수가 아니다.

## 실제 목소리를 넣는 방법

### 추천: 실제 녹음 조각과 음악을 합성

원본 녹음 중 사용자가 고른 3~5초를 음악의 도입부 또는 간주에 넣는다. 예를 들어 “아빠는 이렇게 말했지” 다음에 당시의 실제 말이 나온다. 가장 저렴한 첫 버전은 **도입부 한 곳에 배치**하는 방식이다. 임의의 노래 중간에 자연스럽게 끼워 넣는 것은 곡 구조와 보컬 구간 분석까지 필요하다.

구현 파이프라인은 원본 녹음 → 구간 선택/미리듣기 → 앞뒤 무음 정리 → 볼륨 정규화 → 음악 볼륨을 잠깐 낮추기 → 짧은 페이드 → 새 음원으로 내보내기다. 임시 믹스는 기기에서 재생하고, 공개/저장할 때만 한 번 인코딩하면 서버 CPU와 반복 작업을 줄일 수 있다. MediaCodec/MediaMuxer 또는 라이선스 검토를 마친 오디오 처리 도구로 구현한다.

**현재 앱은 원본 PCM 조각을 저장하지만 음성 조각 선택·최종 음악 믹싱은 제공하지 않는다.** Pleos 실차의 마이크 접근, 통화·음악과의 오디오 포커스, echo cancellation, 백그라운드 동작은 별도로 확인해야 한다. [Android 녹음 API](https://developer.android.com/media/platform/mediarecorder)

### 다른 선택: 목소리 복제

동의를 받은 성인의 음성으로 별도의 음성 복제 서비스를 사용해 짧은 대사를 만드는 방법은 있다. 그러나 TTS 목소리 복제는 그 사람의 목소리로 노래하는 기능과 다르다. 가창 음색 변환에는 별도의 모델과 품질 검증, 권리·제공사 정책 검토가 필요하다. 첫 상용 버전에서는 실제 녹음 삽입을 우선한다. [ElevenLabs Instant Voice Cloning](https://elevenlabs.io/docs/eleven-creative/voices/voice-cloning/instant-voice-cloning)

Lyria 3.5의 공식 API 입력은 텍스트와 이미지이고 출력은 MP3와 가사다. 현재 연결로 참가자의 목소리 샘플이나 로컬 비트를 넣어 동일하게 재현할 수 있다고 안내하면 안 된다. [Lyria 모델 문서](https://ai.google.dev/gemini-api/docs/models/lyria-3.5)

## 장시간 대화와 하이라이트

상용화 시에는 여행 전체를 한 번의 음성 인식 요청으로 처리하지 않는다.

- **수집**: 사용자가 시작하고 탑승자에게 녹음 중임을 명확히 알린다. 차량 데이터는 1분 집계, 음성은 30~60초 단위 조각과 타임스탬프로 저장한다. 30분은 파일/요약 구간이지 전체 여행을 강제로 끝내는 제한으로 쓰지 않는다.
- **절약**: 로컬 음성 활동 감지(VAD)로 긴 무음을 줄인다. Pleos 온디바이스 전사를 우선 검증하고, 인식 실패한 조각만 사용자가 선택해서 서버 전사한다. SDK의 상용 사용 조건과 실제 기기 성능은 확인이 필요하다.
- **복구**: 조각마다 체크포인트를 남겨 통신 단절·앱 종료 후 이미 처리한 부분을 재전송하지 않는다. 작은 오디오 겹침을 두되 타임스탬프와 문장으로 중복을 제거한다.
- **하이라이트**: 도착 후 텍스트를 한 번 분석해 3~5개 후보를 만든다. 발언자 이름은 사용자가 붙인다. 화자 분리는 사람의 실명·가족관계 식별이 아니다.
- **웃음**: 음량이 크다고 웃음이라고 판단하지 않는다. 음성/웃음 분류기나 선택 구간의 오디오 분석이 별도로 필요하다. 결과는 확정 판정이 아닌 후보로 제시한다.
- **음성 보관**: 선택하지 않은 원본은 기본적으로 짧게 보관 후 삭제하고, 선택한 조각만 프로젝트에 남긴다. 사용자가 자동 삭제 시점과 보관 여부를 볼 수 있게 한다.
- **음악과 겹침**: 앱 자체 음악·내비·통화 구간은 구분한다. 스피커에서 나오는 음악을 가족 대화로 전사하지 않도록 실차 소음 테스트를 수행한다.

Pleos STT 공식 이벤트는 중간/최종 텍스트, 발화 시작·끝, 입력 레벨이다. 이야기 요약이나 웃음 분류를 제공한다고 문서화되어 있지 않다. [Pleos 이벤트](https://document.pleos.ai/en/docs/pleos-only/connect-sdk-pleos/SpeechToText/result-listeners)

추가 AI 분석에는 텍스트 요약을 우선 사용하고, 음향 정보가 꼭 필요한 후보 구간에만 오디오 분석을 쓴다. [Gemini 오디오 분석](https://ai.google.dev/gemini-api/docs/audio)

## 같은 주행 시간을 비교할 수 있게 만들기

현재 카운터는 최대 64회의 상태 변화를 저장한다. 상용화에서는 길게 달릴수록 무조건 악기가 많아지지 않게 **분당 이벤트 수**, **와이퍼 활성 시간 비율**, **창문 열림 유지 시간**, **정차 비율**, **가감속 분포**로 바꾼다. 빠른 속도를 좋은 점수처럼 보상하지 않고 템포는 제한된 범위에 둔다. 신호 횟수와 음악의 결과는 홈과 상세 화면에서 설명한다.

## 비용: 곡을 만들 때만 지출

아래는 공식 공개 단가와 계산 예시다. 실제 청구는 토큰 수·요청 길이·재생량·세금 등에 따라 달라진다. [Google 요금](https://ai.google.dev/gemini-api/docs/pricing)

- Lyria 3.5: 새 곡당 **$0.08**.
- 예시 하이라이트 요약: Gemini 3.5 Flash-Lite에 입력 8,000토큰 + 출력 1,000토큰이면, 입력 $0.30/백만·출력 $2.50/백만 기준 **$0.0049**. 길이와 thinking 토큰을 제한해야 하며 이 수치는 가정이다.
- 서버 전사가 필요하면 Gemini 3.5 Transcribe의 공식 추정 합산 단가 약 **$0.005/분** 기준 30분은 **$0.15**. 텍스트 토큰 수에 따라 달라진다. 한 곡 생성보다 전체 대화 전사가 더 비쌀 수 있다.

| 계산 예시 | 1회 | 1,000회 |
| --- | ---: | ---: |
| 기기 전사 + 요약 1회 + 새 곡 1개 | $0.0849 | $84.90 |
| 위 과정 + 30분 서버 전사 | 약 $0.2349 | 약 $234.90 |

위 표는 API 비용만이다. 원본 녹음 삽입은 음성 생성 API 비용이 없지만 기기 배터리/CPU 또는 서버 인코딩 비용이 든다. 저장된 MP3를 기기에서 다시 듣는 것은 생성 토큰을 쓰지 않는다. 다른 사용자의 곡을 다운로드하면 저장·전송 비용은 발생할 수 있다.

Supabase Pro는 기본 $25/월부터다. 3 MB 곡 1,000개는 약 3 GB, 캐시 없는 전체 다운로드 10,000회는 약 30 GB라는 용량 가정으로 산정한다. 무료 플랜은 MVP 검증에 활용하되 상용 운영에서는 휴면 정지, 백업, 저장/전송 한도를 확인한다. [Supabase 요금](https://supabase.com/pricing), [스토리지 전송량](https://supabase.com/docs/guides/storage/serving/bandwidth)

따라서 월 1,000곡을 만드는 기기 전사 시나리오의 단순 부분 합계는 API $84.90 + Pro 기본 $25 = **$109.90**다. 여기에 작업 서버·초과 트래픽·재시도·모니터링·결제 수수료·세금 등이 더해진다. 전체 운영비를 $109.90으로 보장하는 계산이 아니다.

## 운영 구조와 비용 제한

- 모바일/차량 앱 → 인증된 API → 작업 큐 → 음악 생성 작업자 → 비공개 저장소. 현재의 Mac loopback 서버를 그대로 외부 공개하지 않는다.
- 계정별 생성 크레딧을 DB 트랜잭션으로 먼저 예약한다. 중복 클릭·두 기기 동시 요청도 하나의 작업만 만든다. 계정별/전체 일일 한도를 서버에서 강제한다.
- 이야기·이름·설정·편곡 버전으로 동일 요청을 판별한다. 다른 사용자의 비공개 결과를 재사용하지 않는다.
- 생성/다운로드/분석/믹싱의 작업 상태를 분리한다. 다운로드 실패 때문에 유료 생성부터 반복하지 않는다. 응답이 불확실한 유료 요청은 자동 재시도하지 않는다.
- 제목 수정·가사 열기·원본 음성 삽입 위치 변경은 음악 재생성을 유발하지 않는다.
- 가사 시간 정렬은 선택 기능으로 한 번만 분석해 저장한다. 기본 생성 비용에 몰래 분석 호출을 추가하지 않는다.
- 듣는 곡은 로컬 캐시, 공개 피드는 페이지 단위 로딩, 목록에서 모든 곡을 자동 다운로드하지 않는다.
- 예산 알림은 결제의 강제 중지가 아니다. 앱 서버의 요청 한도/크레딧과 공급사 제한을 함께 사용한다.

## 공개 UX와 다음 검증

업로드 직전에 곡 제목, 닉네임, 공유할 가사를 확인한다. 실제 녹음이 있는 곡에만 **“실제 탑승자의 음성이 포함되어 있습니다”**를 표시하고, 녹음 당사자의 공개 동의를 확인한다. AI 목소리를 썼다면 실제 녹음과 혼동되지 않는 별도 라벨을 붙인다. 삭제·신고·소유권 확인·다른 계정 접근 차단까지 검증해야 실제 공유 기능 완료로 판단한다.

우선순위는 ① 현재 UI와 차량 데이터→음악 연결 시연 ② 짧은 실제 목소리 녹음·미리듣기·도입부 삽입 ③ 사용자 선택 기반 하이라이트 ④ 장시간 수집 안정화 ⑤ 계정과 실제 공개 서비스다. 영상은 사용자 제공 사진/영상과 시간 정보를 활용한 60초 편집으로 확장한다. 공개 Pleos API만으로 블랙박스 영상을 가져올 수 있다고 가정하지 않는다.
